# 练习里的时间怎么算

唯一时钟是 `AudioContext.currentTime`。`RhythmTrainer.tsx` 不读取 `performance.now()`，也不使用动画帧回调提供的时间戳。`App.tsx` 负责页面路由和公共导航，`PracticePage.tsx` 根据题目地址提供练习参数。

## 先分清两件事

1. **时间线**：谱子决定“应该什么时候发生什么”，与点击开始的时刻无关。
2. **时钟**：本轮练习“现在进行到哪里了”，点击开始后才建立。

`RhythmTiming.ts` 的 `createExerciseTimeline()` 根据配置生成时间线。`RhythmAudio.ts` 的 `createPracticeClock()` 建立本轮时钟。`RhythmTrainer.tsx` 用时钟读数查询时间线。

## 训练组件参数

```tsx
<RhythmTrainer exercise={exercise} bpm={60} />
```

`exercise` 和 `bpm` 必传；`countInBeatCount` 默认 3，`timingWindows` 默认 `{ perfectMs: 50, hitMs: 150 }`。模式、播放状态、判定记录和音频资源由训练组件内部管理。

组件通过 `useMemo` 根据练习、BPM、预备拍数和判定窗口生成时间线。判定窗口按 `perfectMs`、`hitMs` 两个数值建立依赖，因此传入等值新对象不会重建时间线。练习内容不变时，父组件应保持 `exercise` 引用稳定；修改内容时应创建新对象，不要原地修改。

`data/presetExercises.ts` 按“主题 → 模式 → 题目”组织七个主题的 31 道击拍题目（分别为 3、6、5、5、4、4、4 道，包含 2、3、4、6、8 小节的练习）。每个主题的听写和几何游戏题库独立且暂为空。练习库在主题内选择模式并列出其题目；`PracticePage` 从 `/practice/:questionId` 查找题目及所属模式，只有 tapping 进入击拍组件，并提供 BPM 输入（40–240 的整数）。输入速度是草稿，点击“应用速度”或回车后才生效。预备拍数和判定窗口使用组件默认值。

`PracticePage` 使用题目 ID 重建配置区域，并使用题目 ID 和生效 BPM 组合成训练组件的 `key`。任一生效值改变时，React 卸载旧实例并创建新实例，旧实例负责取消 RAF、停止排程声音、关闭音频上下文、作废异步启动；新实例从空的判定记录和未开始状态运行。应用相同 BPM 或只编辑草稿不会重建组件。返回练习库或离开练习页也会卸载训练；刷新、换题及重新进入页面恢复默认 60 BPM，不保存进行中的一轮。

界面不重复显示生效 BPM；输入草稿不同于生效值时提示“未应用”，提交非法值时显示错误并保留当前轮。闲置状态不显示占位反馈；播放期间显示预备拍或即时判定，击拍结束只显示结果并保留谱面标记；试听显示进行中/结束状态，不生成练习结果。这些显示规则不改变时间线或判定逻辑。

这是当前页面对配置变化的处理。`RhythmTrainer` 本身尚未实现原地变更 props 时自动停止；其他调用方也应在配置改变时重建实例，或等待后续补齐组件内部规则。


事件支持 `dots?: 0 | 1`：省略或 0 为无附点，1 为单附点，音符和休止符共用。`rhythmEventToDurationInQuarterNotes()` 统一计算完整事件时值（单附点为基本时值 × 1.5），时间线和连梁分组都调用它。VexFlow 的 `dots` 设置内部时值，`Dot` modifier 绘制附点；声音和判定不增加专用分支。附点八分音符暂不参与普通八分音符两两连梁。附点全音符虽然可计算为六拍，但不能放进当前四拍小节。

## 统一零点与单位

练习模型使用 `measures: { events: RhythmEvent[] }[]` 显式表达小节，不再使用顶层 events。小节数由内容决定，整份练习共用 4/4 拍号；约定每小节填满四拍，事件不跨小节。生成时间线前调用 `validateRhythmExercise()`，拒绝欠拍、超拍和空小节，错误包含小节编号与实际拍数；不自动补拍或拆分。零小节仍可表示空练习，全小节休止必须显式录入休止符。这是类型化内容的校验，不是任意外部 JSON 的结构解析。

时间线按小节顺序连续累计，不在小节边界重置时钟或添加预备拍。`eventIndex` 是包含休止符的全局事件下标，不是小节内编号。时间线额外提供 `measures`（startOffsetMs、endOffsetMs、firstEventIndex）和 `eventStartOffsetsMs`，渲染层不重复计算 BPM 或小节时间。

例如 BPM 60，两小节分别为两个二分音符、一个全音符：目标起点为 [0, 2000, 4000]ms，事件终点为 [2000, 4000, 8000]ms；只有整份练习结束才统计结果。

正式练习开始是 `0ms`。预备拍在负数区间；练习进行中是非负数。业务层全部用相对毫秒，音频 API 的绝对秒数封装在 `RhythmAudio.ts`。

假设 BPM 为 60、三拍预备拍、100ms 调度缓冲：

| 相对正式练习起点 | 事件 |
| --- | --- |
| -3100ms | 音频准备完成、创建本轮时钟，画面显示“准备中” |
| -3000ms | 第一声预备拍，显示预备拍 1 |
| -2000ms | 第二声预备拍，显示预备拍 2 |
| -1000ms | 第三声预备拍，显示预备拍 3 |
| 0ms | 正式练习开始，第一个音符起点 |
| 150ms | 击拍模式下，若第一拍未命中，允许判定 miss |

100ms 是给音频提前排程的余量，不属于预备拍或音符时值。以 `resume()` 完成后的音频时间为起点，等待恢复音频的耗时不计入练习。

## 同一个时钟的两个接口

```ts
clock.nowMs()                 // 本轮现在进行到哪一毫秒
clock.audioTimeAt(offsetMs)   // 这个相对时刻对应音频时间轴上的第几秒
```

转换公式只在 `RhythmAudio.ts` 出现：

```text
正式起点秒数 = 当前音频秒数 + (缓冲毫秒 + 预备拍总毫秒) / 1000
当前相对毫秒 = (当前音频秒数 - 正式起点秒数) × 1000
排程绝对秒数 = 正式起点秒数 + 事件相对毫秒 / 1000
```

例如创建时音频时间是 10 秒，正式起点就是 13.1 秒。第一声预备拍排在 10.1 秒。音频时间走到 14.15 秒时，`nowMs()` 约为 1050。

## 谱子如何变成时间线

当前 BPM 以四分音符为单位：一拍毫秒数 = `60000 / BPM`。

事件时长 = 一拍毫秒数 × 四分音符单位的时值。全音符为 4，二分音符为 2，四分音符为 1，八分音符为 0.5。依次累加得到每个事件的起点和终点；对应休止符也参与累计，但不生成敲击目标。长音符只在起点生成一个目标，不要求长按；试听仍是一次短击拍音，不按时值持续发声。BPM 60 的全音符目标在 0ms，事件结束在 4000ms；中途多敲属于误敲，命中窗口不会随音符时长扩大。

### 新增音符时修改哪些地方

- `RhythmModel.ts`：扩展 NoteValue，以及到四分音符单位时值的换算。
- `RhythmScore.tsx`：增加 VexFlow duration 映射；whole → w、half → h、quarter → q、eighth → 8，休止符追加 r。保持乐谱库编码位于显示层，不放入核心模型。
- `data/presetExercises.ts`：按需增加预设练习，不是底层支持的必要步骤。
- 测试：验证时间线、目标数量、混合时值、休止符、BPM 缩放及结束边界；谱面另做渲染验证。

新增普通时值无需改动音频时钟、声音排程、匹配、漏拍与结果统计：它们使用展开后的偏移时间和目标记录。试听高亮也沿用事件终点。这一约定不自动覆盖连音线、复附点或连音组等额外记谱语义。

以时间测试中的单小节 `Q Q Q EE` 在 BPM 60 下为例（不是当前预设题）：

| 音符 | 起点 ms | 终点 ms | 命中窗口 ms |
| --- | --- | --- | --- |
| 四分 | 0 | 1000 | [-150, 150) |
| 四分 | 1000 | 2000 | [850, 1150) |
| 四分 | 2000 | 3000 | [1850, 2150) |
| 八分 | 3000 | 3500 | [2850, 3150) |
| 八分 | 3500 | 4000 | [3350, 3650) |

试听模式下，高亮的逻辑切换时刻是音符起点；击拍模式下不显示音符高亮，未命中目标从窗口关闭时起可以判为 miss。以当前窗口设置计算，漏拍的逻辑时刻比目标起点晚 150ms，实际标记会在后续画面更新中呈现。

两种模式目前共用结束时刻：取“谱子总时长”和“最后一个目标窗口关闭时间”中较晚的那个。击拍模式结束前先收齐未判定的过期目标，不需要人为追加 1ms 来竞争定时器顺序。当前预设在 BPM 60、默认窗口下，按小节数分别在 8000、12000、16000、24000、32000ms 结束（不含预备拍）；若以后使用时值短于命中窗口的末尾音符，试听也会暂时保留这段等待时间。

## 击拍与试听模式

`mode` 表示本轮用途（practice / listen），`phase` 表示运行阶段。模式在开始时确定，播放中另一个模式按钮禁用，当前按钮用于停止；等待音频恢复时两个按钮都禁用。

| 行为 | 击拍 practice | 试听 listen |
| --- | --- | --- |
| 预备拍声音与倒数 | 有 | 有 |
| 自动播放音符 | 无 | 有，休止符不响 |
| 当前音符高亮 | 无 | 有 |
| 空格击拍音与判定 | 有 | 无 |
| 自动漏拍与判定文字 | 有 | 无 |

两种模式共用时间线、本轮时钟和 RAF 循环。每次开始清空上一轮的判定记录。模式不改变既有匹配规则。

## RhythmTrainer 每次做什么

预备拍声音提前用 `audioTimeAt()` 和 `scheduleCountIn()` 安排，使用较高的三角波提示音（重拍 1350Hz，普通拍 900Hz）。试听模式额外遍历 `timeline.targetTaps`，通过 `scheduleTapSound()` 在每个音符起点安排较低的击拍音（600Hz 正弦波），音色与用户空格击拍一致。休止符不生成目标，所以不发声，但仍占用时长。预备拍和试听音都保存在 `scheduledSourcesRef` 中。

击拍模式的用户击拍音则在按键发生、通过输入检查之后调用 `playTapSound()`，内部调用同一个 `scheduleTapSound()`，使用当时的音频时间立即排程，不添加 100ms 调度余量。试听和空格击拍共用音色实现，区别只在于排程时间与声源是否加入可取消列表。

页面只有一条 `requestAnimationFrame` 更新循环：

1. 读取一次 `clock.nowMs()`。
2. `recordExpiredTargets()` 在击拍模式补齐截至此刻的漏拍并推进匹配游标；试听模式直接返回。
3. `getPlaybackPosition()` 根据此刻定位预备拍或音符。
4. 显示位置变化才更新 React 状态；到终点则结束本轮。

输入框、下拉框、按钮和可编辑区域内的空格保留控件自己的行为，不作为击拍。其他位置按空格时先确认本轮时钟存在、音频处于运行状态，并忽略长按产生的重复事件。试听模式阻止空格的默认行为后直接返回，不发出击拍音或产生判定。击拍模式继续读取 `clock.nowMs()`，补齐过期目标；如果已经到整轮终点则忽略本次敲击。正式开始前，只有第一个待敲击目标窗口内、且该目标尚未判定的输入才继续处理。

通过这些检查后，先播放击拍音，再用已经记录的 `tapOffsetMs` 匹配目标。创建声音节点的耗时不会被追加到这次判定时间中。`wrongTap` 也会播放击拍音。命中的误差 = 敲击相对毫秒 - 目标起点相对毫秒。游标使用 ref 同步更新，避免连续事件在 React 渲染前重复命中同一个目标。

## 当前匹配规则

`evaluateTap()` 只检查 `nextTargetIndex` 指向的最靠前待判定目标，不搜索时间上最近的目标。调用者先补齐漏拍、推进游标，再进行匹配。窗口采用左闭右开区间；窗口内绝对误差不超过 `perfectMs` 为 perfect，其余负误差为 early，正误差为 late。

相邻窗口可以重叠。例如 BPM 120 的连续八分音符起点为 0ms、250ms，窗口分别为 [-150, 150)、[100, 400)。在 140ms 敲击时，如果第一个目标尚未判定，则匹配第一个目标并判为 late；若第一个目标已判定、游标指向第二个目标，则匹配第二个目标并判为 early。这是当前的顺序匹配规则。

早于下一个目标窗口的敲击，以及目标全部判定完毕后、本轮结束前的敲击，统一返回 `{ kind: "wrongTap", tapOffsetMs }`。误敲不区分原因，不保存参考目标或误差，不推进游标；每次有效误敲分别记录，文字显示“误敲”，谱面按敲击时间显示粗红叉。例如最后一个目标在 3500ms 已命中，在 3750ms 再敲一次，距离整轮 4000ms 的终点尚有时间，所以会发声并新增误敲记录。最后目标漏拍后继续敲击也采用同一规则。

判定函数不负责判断整轮是否结束；调用者过滤无效输入时间后才调用它。若调用者尚未清理过期目标，敲击到达该目标窗口右边界时仍返回 null；漏拍由过期检查负责。

## 多小节谱面与反馈位置

`RhythmScore` 接收整份时间线，每小节单独创建 Stave，按容器宽度以完整小节换行。每行显示谱号，仅第一小节显示拍号，最后一小节使用终止线；极窄容器统一缩放谱面与反馈，暂不跟随滚动。高亮及 hit/miss 标记按全局事件下标关联对应音符。

每小节渲染后收集所有事件（含休止符）的时间和横坐标，再添加小节结束锚点。`RhythmScoreLayout.ts` 中的纯函数先按误敲时间选择小节，再在该小节锚点之间插值计算 X，Y 使用该小节所在行的反馈基线；边界属于后一小节，首尾越界限制在谱面范围内。单个全音符或全休止符也有起止两个锚点，因此不同时间的误敲能分布到不同位置。这是谱面显示映射，不参与判定，也不表示 VexFlow 的排版是严格等比例时间轴。


同一四分拍内、从拍头开始的两个八分音符连梁，不跨拍或小节，休止符断开分组。`RhythmScoreLayout.ts` 按音乐时值生成小节内分组，渲染层在排版前创建 VexFlow Beam、排版后绘制。每个音符仍独立播放、判定与高亮，共用连梁保持黑色；数据模型和时间线不变。

## 回调延迟、暂停与停止

动画帧只是检查机会，不是时钟。页面卡顿或隐藏期间画面和漏拍反馈可能延迟；恢复后直接定位到正确位置并补齐漏拍，不逐拍补播。音频暂停后音频时钟停止推进，检查循环也不会提前判漏拍。

停止时清除本轮时钟，取消 RAF 循环，并通过 `stopScheduledSounds()` 停止已保存的预备拍和试听声源；重新开始建立新的时钟和游标。用户击拍音没有保存在排程声源数组中，停止练习时已响起的击拍音会自行完成剩余短尾音（音频时间总长 50ms）并断开节点。组件卸载时取消循环、停止预备拍和试听声音并关闭音频上下文。

统一时钟不等于完成设备延迟校准：音频输出延迟、键盘事件到达 JavaScript 的延迟仍然存在。当前 UI 也受动画帧频率限制。

## 练习结果

`summarizePractice(targetCount, timingEvents)` 是纯统计函数，接收同一轮自然结束后的完整记录：每个目标恰好对应一次 hit 或 miss。它返回目标数、命中数、漏敲数、误敲数与 passed；perfect / early / late 均计入命中。通过条件是所有目标命中、没有漏敲且没有误敲。零目标且没有误敲也通过。

`RhythmTrainer` 仅在击拍模式的 finished 阶段，从当前判定记录直接计算结果，显示“通过 / 未通过”，不增加结果 state 或完成回调。结束帧先补齐漏拍，再更新阶段；统计在状态更新后的渲染中进行，不在 setTimingEvents 后立即读取旧记录。自然结束保留谱面反馈；手动停止和试听不显示结果，成功重新开始或配置切换导致组件重建后旧结果消失。

## 验证

在 frontend 目录执行 `npm test`，运行 `tests/rhythm-time.test.mjs` 中的 31 个测试和 `tests/exercise-library.test.mjs` 中的 5 个内容测试（包括模式归属与题库隔离）。命令明确指定这两个文件，文件缺失时会报错退出，避免通配符未匹配文件时以“0 个测试”成功结束。

测试使用 Node 内置测试工具，并复用 Vite 加载 TypeScript 模块，不启动 HTTP 服务。覆盖时钟换算与暂停、重新开始、调度余量、时值与 BPM、首尾休止符、空练习、显示边界、命中窗口边界、延迟后补判、结束边界、重叠窗口顺序匹配，以及窗口前误敲不消耗目标、目标耗尽后的连续误敲。

结果统计测试覆盖所有命中等级、漏敲、误敲及其组合、零目标、计数准确性、输入记录不被修改，以及结束前补齐漏拍后再汇总。

多小节测试覆盖连续时间、全局事件编号、整小节休止、跨界提前命中、最终结算，以及误敲位置的插值和边界限制。

这些是时间模型和纯判定/统计/位置映射函数的测试：音频暂停通过固定模拟时钟读数验证，不代表真实浏览器暂停测试；声音是否可听、键盘监听、结果展示、React/RAF 生命周期和设备延迟仍需浏览器验证。
