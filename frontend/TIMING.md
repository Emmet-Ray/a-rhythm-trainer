# 练习里的时间怎么算

唯一时钟是 `AudioContext.currentTime`。`RhythmTrainer.tsx` 不读取 `performance.now()`，也不使用动画帧回调提供的时间戳。`App.tsx` 负责页面路由和公共导航，`PracticePage.tsx` 根据题目地址提供练习参数。

## 先分清两件事

### 可开关节拍器

节拍器素材为 `public/assets/audio/metronome.mp3`，保留用户提供的原文件（约 0.816 秒，24 kHz 双声道）。能量检测显示主要起音约在 46ms，播放从 44ms 开始取 200ms，1ms 淡入、最后 20ms 淡出；强拍增益 0.7，普通拍 0.45，不改变播放速率。该截取参数仅针对当前素材，替换文件需重新检查。素材由用户提供并声明免费使用，来源链接及具体许可尚待补充。

`prepareMetronomeSound()` 与钢琴采样并行准备，各自按 AudioContext 缓存与去重，失败允许重试。两种练习都等待采样就绪后才建立时钟，避免首次加载推迟实际起音；关闭正式节拍器仍会加载该素材，供预备拍使用。

练习页的“节拍器”默认开启，控制正式阶段的节拍器声部，预备拍始终保留。`metronomeEnabled` 作为独立 prop 传给击拍与听写组件，不参与时间线或播放器 key；切换不清空击拍记录、听写草稿或判定结果。当前页面内修改 BPM 保留开关选择，换题重置为开启。

`RhythmAudio.createMetronome()` 使用同一 `PracticeClock`，提前安排正式起点至谱子终点之前的四分拍，每小节第一拍重音。它复用预备拍的 metronome.mp3 采样音色，但使用独立声源列表，钢琴声不受开关影响。关闭时取消本声部，重新开启时只安排下一个原定拍点及之后的声音，不立即补响、不重置拍位。休止符、长音和空白答案小节也持续计拍；谱子结束处不额外打一拍，也不延伸到击拍判定的额外等待窗口。

停止、切换播放入口、修改 BPM、换题、离开页面和本轮结束时释放该声部。拍点由音频时钟排程，不由 RAF 触发；RAF 仍只处理界面和结束收尾。这里没有空闲时独立运行的节拍器。

击拍谱面反馈统一为圆形：命中是绿色实心圆，漏拍是红色空心圆，二者位于对应音符下方；误敲是红色实心圆，按实际敲击时间定位。三种标记外径一致，只改变绘制样式，不影响判定、时间映射或结果统计。

击拍和听写共用 `RhythmNotation.ts` 的单线节奏记谱规则：只显示中线，行首使用打击乐谱号，普通音符统一向上。VexFlow 内部仍保留五线坐标，以维持休止符、拍号和附点定位；这只是显示方式，不增加音高数据或改变时值。击拍反馈以可见中线下方 32px 为基准，随谱面统一缩放。

1. **时间线**：谱子决定“应该什么时候发生什么”，与点击开始的时刻无关。
2. **时钟**：本轮练习“现在进行到哪里了”，点击开始后才建立。

`RhythmTiming.ts` 的 `createExerciseTimeline()` 根据配置生成时间线。`RhythmAudio.ts` 的 `createPracticeClock()` 建立本轮时钟。`RhythmTrainer.tsx` 用时钟读数查询时间线。

## 训练组件参数

```tsx
<RhythmTrainer exercise={exercise} bpm={60} />
```

`exercise` 和 `bpm` 必传；`countInBeatCount` 默认取拍号中的拍数，当前 4/4 为四拍（一个小节），显式指定非负整数可覆盖，0 表示关闭预备拍。`timingWindows` 默认 `{ perfectMs: 50, hitMs: 150 }`。模式、播放状态、判定记录和音频资源由训练组件内部管理。

击拍、试听与听写共用 `createCountInTimeline()`，由同一份预备拍总时长与负时间偏移驱动时钟和声音排程。60 BPM 的默认 4/4 预备拍为 `[-4000, -3000, -2000, -1000]ms`，正式题目仍从 0ms 开始；120 BPM 时这些时长减半。当前节奏模型仍只支持 4/4，尚未开放 2/4、3/4 或复合拍号。

组件通过 `useMemo` 根据练习、BPM、预备拍数和判定窗口生成时间线。判定窗口按 `perfectMs`、`hitMs` 两个数值建立依赖，因此传入等值新对象不会重建时间线。练习内容不变时，父组件应保持 `exercise` 引用稳定；修改内容时应创建新对象，不要原地修改。

`data/presetExercises.ts` 按“主题 → 模式 → 题目”组织十三个主题的 58 道击拍题目（分别为 3、6、5、5、4、4、4、5、4、4、4、5、5 道，包含 2、3、4、5、6、8 小节的练习）。每个主题的听写和几何游戏题库独立且暂为空。练习库在主题内选择模式并列出其题目；`PracticePage` 从 `/practice/:questionId` 查找题目及所属模式，只有 tapping 进入击拍组件，并提供 BPM 输入（40–240 的整数）。输入速度是草稿，点击“应用速度”或回车后才生效。预备拍数和判定窗口使用组件默认值。

`PracticePage` 使用题目 ID 重建配置区域，并使用题目 ID 和生效 BPM 组合成训练组件的 `key`。任一生效值改变时，React 卸载旧实例并创建新实例，旧实例负责取消 RAF、停止排程声音、关闭音频上下文、作废异步启动；新实例从空的判定记录和未开始状态运行。应用相同 BPM 或只编辑草稿不会重建组件。返回练习库或离开练习页也会卸载训练；刷新、换题及重新进入页面恢复默认 60 BPM，不保存进行中的一轮。

界面不重复显示生效 BPM；输入草稿不同于生效值时提示“未应用”，提交非法值时显示错误并保留当前轮。闲置状态不显示占位反馈；播放期间显示预备拍或即时判定，击拍结束只显示结果并保留谱面标记；试听显示进行中/结束状态，不生成练习结果。这些显示规则不改变时间线或判定逻辑。

这是当前页面对配置变化的处理。`RhythmTrainer` 本身尚未实现原地变更 props 时自动停止；其他调用方也应在配置改变时重建实例，或等待后续补齐组件内部规则。


事件支持 `dots?: 0 | 1`：省略或 0 为无附点，1 为单附点，音符和休止符共用。`rhythmEventToDurationInQuarterNotes()` 统一计算完整事件时值（单附点为基本时值 × 1.5），普通事件经它换算后转为整数 tick，再由统一展开结果供时间线和连梁分组使用。VexFlow 的 `dots` 设置内部时值，`Dot` modifier 绘制附点；声音和判定不增加专用分支。十六分音符使用 `noteValue: "sixteenth"`，基本时值为 0.25 拍，对应休止符与单附点也支持。附点全音符虽然可计算为六拍，但不能放进当前四拍小节。

## 统一零点与单位

练习模型使用 `measures: { elements: RhythmElement[] }[]` 显式表达小节，小节不再使用 events 字段。小节数由内容决定，整份练习共用 4/4 拍号；约定每小节填满四拍，事件不跨小节。生成时间线前调用 `validateRhythmExercise()`，拒绝欠拍、超拍和空小节，错误包含小节编号与实际拍数；不自动补拍或拆分。零小节仍可表示空练习，全小节休止必须显式录入休止符。这是类型化内容的校验，不是任意外部 JSON 的结构解析。

时间线按小节顺序连续累计，不在小节边界重置时钟或添加预备拍。`eventIndex` 是包含休止符的全局事件下标，不是小节内编号。时间线额外提供 `measures`（startOffsetMs、endOffsetMs、firstEventIndex）和 `eventStartOffsetsMs`，渲染层不重复计算 BPM 或小节时间。

例如 BPM 60，两小节分别为两个二分音符、一个全音符：目标起点为 [0, 2000, 4000]ms，事件终点为 [2000, 4000, 8000]ms；只有整份练习结束才统计结果。

正式练习开始是 `0ms`。预备拍在负数区间；练习进行中是非负数。业务层全部用相对毫秒，音频 API 的绝对秒数封装在 `RhythmAudio.ts`。

以下为显式设置三拍预备拍的示例（不是当前默认值），假设 BPM 为 60、100ms 调度缓冲：

| 相对正式练习起点 | 事件 |
| --- | --- |
| -3100ms | 音频准备完成、创建本轮时钟，画面显示“准备中” |
| -3000ms | 第一声预备拍，显示预备拍 1 |
| -2000ms | 第二声预备拍，显示预备拍 2 |
| -1000ms | 第三声预备拍，显示预备拍 3 |
| 0ms | 正式练习开始，第一个音符起点 |
| 150ms | 击拍模式下，若第一拍未命中，允许判定 miss |

100ms 是给音频提前排程的余量，不属于预备拍或音符时值。等待 `resume()` 和 `prepareTapSound()`（钢琴采样下载/解码）都完成后，才读取音频时间建立时钟；这些等待不计入练习。

## 同一个时钟的两个接口

```ts
clock.nowMs()                 // 本轮现在进行到哪一毫秒
clock.audioTimeAt(offsetMs)   // 这个相对时刻对应音频时间轴上的第几秒
```

转换公式只在 `RhythmAudio.ts` 出现：

```text
正式起点秒数 = 当前音频秒数 + (缓冲毫秒 + 预备拍总毫秒) / 1000
当前相对毫秒 = (当前音频秒数 - 正式起点秒数) × 1000
排程绝对秒数 = 正式起点秒数 + 事件相对毫秒 / 1000
```

例如创建时音频时间是 10 秒，正式起点就是 13.1 秒。第一声预备拍排在 10.1 秒。音频时间走到 14.15 秒时，`nowMs()` 约为 1050。

## 谱子如何变成时间线

当前 BPM 以四分音符为单位：一拍毫秒数 = `60000 / BPM`。

事件时长 = 一拍毫秒数 × 四分音符单位的时值。全音符为 4，二分音符为 2，四分音符为 1，八分音符为 0.5，十六分音符为 0.25；单附点再乘以 1.5。依次累加得到每个事件的起点和终点；对应休止符也参与累计，但不生成敲击目标。长音符只在起点生成一个目标，不要求长按；试听与听写在目标音符终点收音，用户击拍则播放固定长度的短音。BPM 60 的全音符目标在 0ms，事件结束在 4000ms；中途多敲属于误敲，命中窗口不会随音符时长扩大。

### 新增音符时修改哪些地方

- `RhythmModel.ts`：扩展 NoteValue，以及到四分音符单位时值的换算。
- `RhythmScore.tsx`：增加 VexFlow duration 映射；whole → w、half → h、quarter → q、eighth → 8、sixteenth → 16，休止符追加 r。保持乐谱库编码位于显示层，不放入核心模型。
- `data/presetExercises.ts`：按需增加预设练习，不是底层支持的必要步骤。
- 测试：验证时间线、目标数量、混合时值、休止符、BPM 缩放及结束边界；谱面另做渲染验证。

新增普通时值无需改动音频时钟、声音排程、匹配、漏拍与结果统计：它们使用展开后的偏移时间和目标记录。试听高亮也沿用事件终点。这一约定不自动覆盖连音线、复附点或其他连音组等额外记谱语义。

以时间测试中的单小节 `Q Q Q EE` 在 BPM 60 下为例（不是当前预设题）：

| 音符 | 起点 ms | 终点 ms | 命中窗口 ms |
| --- | --- | --- | --- |
| 四分 | 0 | 1000 | [-150, 150) |
| 四分 | 1000 | 2000 | [850, 1150) |
| 四分 | 2000 | 3000 | [1850, 2150) |
| 八分 | 3000 | 3500 | [2850, 3150) |
| 八分 | 3500 | 4000 | [3350, 3650) |

试听模式下，高亮的逻辑切换时刻是音符起点；击拍模式下不显示音符高亮，未命中目标从窗口关闭时起可以判为 miss。以当前窗口设置计算，漏拍的逻辑时刻比目标起点晚 150ms，实际标记会在后续画面更新中呈现。

两种模式目前共用结束时刻：取“谱子总时长”和“最后一个目标窗口关闭时间”中较晚的那个。击拍模式结束前先收齐未判定的过期目标，不需要人为追加 1ms 来竞争定时器顺序。当前预设在 BPM 60、默认窗口下，按小节数分别在 8000、12000、16000、20000、24000、32000ms 结束（不含预备拍）；若以后使用时值短于命中窗口的末尾音符，试听也会暂时保留这段等待时间。

## 击拍与试听模式

`mode` 表示本轮用途（practice / listen），`phase` 表示运行阶段。模式在开始时确定，播放中另一个模式按钮禁用，当前按钮用于停止；等待音频恢复时两个按钮都禁用。

| 行为 | 击拍 practice | 试听 listen |
| --- | --- | --- |
| 预备拍声音与倒数 | 有 | 有 |
| 自动播放音符 | 无 | 有，休止符不响 |
| 当前音符高亮 | 无 | 有 |
| 空格击拍音与判定 | 有 | 无 |
| 自动漏拍与判定文字 | 有 | 无 |

两种模式共用时间线、本轮时钟和 RAF 循环。每次开始清空上一轮的判定记录。模式不改变既有匹配规则。

## 听写题目与草稿播放

`RhythmDictationPlayback` 共用一个音频上下文与声源列表，提供“播放题目”和“播放我的答案”；切换入口先取消旧声音和未完成的加载请求。同一入口再次点击停止，换题、修改 BPM 或卸载时清理播放器。

听写与击拍共用 `PracticePage` 的 BPM 表单：默认 60，接受 40–240 的整数，点击“应用速度”或回车后生效。只编辑输入、提交非法值或应用相同 BPM 不停止播放。听写的生效 BPM 改变时，仅通过内部播放器的 key 取消旧播放和异步启动，不重建答题组件，因此草稿、验证结果、选中小节、播放范围和参考答案展开状态均保留。换题通过外层题目 key 重置整个练习页和 BPM。

“整题／当前小节”范围由两个播放入口共用，默认整题。当前小节模式只传入选中的题目小节与答案小节，时间线从该小节的 0ms 开始，不播放前面的小节，仍使用一小节预备拍和完整小节时长。答案按钮按所选范围是否为空决定是否禁用。切换范围或选中小节（整题模式下也包括）时通过 key 重建播放器，取消旧声音及未完成请求，但不重置草稿、范围选择或验证结果。播放器重建也会关闭旧音频上下文，新播放重新准备声音。

两种播放均由 `createDictationPlaybackTimeline()` 按当前 BPM 展开音乐时值，使用相同的一小节预备拍与钢琴音色，不使用击拍判定窗口。草稿允许未填满：每小节仍占完整四拍，未填写部分、空白小节及末尾空白小节保持静默，不向答案数组补休止符。全空草稿禁止启动答案播放；只有休止符的草稿可以播放静默时值。

每次点击固定一份起止时间排程。播放时允许继续编辑，已安排的声音不随草稿变化，下次播放使用最新草稿；播放不清空答案、不改变判题结果、不高亮草稿。即使播放中删空答案，停止按钮仍可用。

## RhythmTrainer 每次做什么

预备拍声音提前用 `audioTimeAt()` 和 `scheduleCountIn()` 安排，使用 metronome.mp3 单次采样，强弱拍只改变增益，不改变音高。试听模式额外遍历 `timeline.targetTaps`，通过 `scheduleTapSound()` 在每个音符起点安排钢琴采样，音色与用户空格击拍和听写播放一致。休止符不生成目标，所以不发声，但仍占用时长。预备拍、试听音和用户击拍音都保存在 `scheduledSourcesRef` 中，停止或卸载时一起取消。

击拍模式在按键通过输入检查且判定为命中或误敲后调用 `playTapSound()`，内部调用同一个 `scheduleTapSound()`，使用当时的音频时间立即排程，不添加 100ms 调度余量，也不等待下载或解码。命中与误敲使用相同的 200ms 钢琴短音。采样按 AudioContext 缓存，加载失败可重试。

钢琴参数集中在 `RhythmAudio.ts`：从原始采样 10ms 处开始，增益 0.7，起音淡入最多 2ms。`scheduleTapSound()` 接收音频绝对起止秒数，在指定终点前淡出并归零，淡出长度取 80ms 与实际发声长度的四分之一中较小值。试听与听写传入目标起点和 `eventEndOffsetsMs[target.eventIndex]` 对应的终点；用户敲击先判定，命中与误敲均调用 `playTapSound()` 立即播放固定 200ms 的同音色短音，包含末尾 50ms 淡出。击拍反馈不接收目标终点，不随 BPM、音符时值或早晚误差改变长度；长度统一由 `TAP_SOUND_SECONDS` 控制。若素材先播完则自然结束，不循环或拉伸采样。原始 MP3、音符时间线和敲击判定时间均保持不变。

页面只有一条 `requestAnimationFrame` 更新循环：

1. 读取一次 `clock.nowMs()`。
2. `recordExpiredTargets()` 在击拍模式补齐截至此刻的漏拍并推进匹配游标；试听模式直接返回。
3. `getPlaybackPosition()` 根据此刻定位预备拍或音符。
4. 显示位置变化才更新 React 状态；到终点则结束本轮。

输入框、下拉框、按钮和可编辑区域内的空格保留控件自己的行为，不作为击拍。其他位置按空格时先确认本轮时钟存在、音频处于运行状态，并忽略长按产生的重复事件。试听模式阻止空格的默认行为后直接返回，不发出击拍音或产生判定。击拍模式继续读取 `clock.nowMs()`，补齐过期目标；如果已经到整轮终点则忽略本次敲击。正式开始前，只有第一个待敲击目标窗口内、且该目标尚未判定的输入才继续处理。

通过这些检查后，先用已经记录的 `tapOffsetMs` 匹配目标，命中与误敲均播放相同的击拍音。创建声音节点的耗时不会被追加到这次判定时间中。`wrongTap` 照常记录视觉反馈和结果统计，不推进目标游标。命中的误差 = 敲击相对毫秒 - 目标起点相对毫秒。游标使用 ref 同步更新，避免连续事件在 React 渲染前重复命中同一个目标。

## 当前匹配规则

`evaluateTap()` 只检查 `nextTargetIndex` 指向的最靠前待判定目标，不搜索时间上最近的目标。调用者先补齐漏拍、推进游标，再进行匹配。窗口采用左闭右开区间；窗口内绝对误差不超过 `perfectMs` 为 perfect，其余负误差为 early，正误差为 late。

相邻窗口可以重叠。例如 BPM 120 的连续八分音符起点为 0ms、250ms，窗口分别为 [-150, 150)、[100, 400)。在 140ms 敲击时，如果第一个目标尚未判定，则匹配第一个目标并判为 late；若第一个目标已判定、游标指向第二个目标，则匹配第二个目标并判为 early。这是当前的顺序匹配规则。

早于下一个目标窗口的敲击，以及目标全部判定完毕后、本轮结束前的敲击，统一返回 `{ kind: "wrongTap", tapOffsetMs }`。误敲不区分原因，不保存参考目标或误差，不推进游标；每次有效误敲分别记录，文字显示“误敲”，谱面按敲击时间显示红色实心圆。例如最后一个目标在 3500ms 已命中，在 3750ms 再敲一次，距离整轮 4000ms 的终点尚有时间，所以会发声并新增误敲记录。最后目标漏拍后继续敲击也采用同一规则。

判定函数不负责判断整轮是否结束；调用者过滤无效输入时间后才调用它。若调用者尚未清理过期目标，敲击到达该目标窗口右边界时仍返回 null；漏拍由过期检查负责。

## 多小节谱面与反馈位置

`RhythmScore` 接收整份时间线，每小节单独创建 Stave，按容器宽度以完整小节换行。每行显示谱号，仅第一小节显示拍号，最后一小节使用终止线；极窄容器统一缩放谱面与反馈，暂不跟随滚动。高亮及 hit/miss 标记按全局事件下标关联对应音符。

每小节渲染后收集所有事件（含休止符）的时间和横坐标，再添加小节结束锚点。`RhythmScoreLayout.ts` 中的纯函数先按误敲时间选择小节，再在该小节锚点之间插值计算 X，Y 使用该小节所在行的反馈基线；边界属于后一小节，首尾越界限制在谱面范围内。单个全音符或全休止符也有起止两个锚点，因此不同时间的误敲能分布到不同位置。这是谱面显示映射，不参与判定，也不表示 VexFlow 的排版是严格等比例时间轴。


同一四分拍内的连续八分、十六分音符（含单附点）可混合连梁，支持 EE、SSSS、ESS、SSE、E.S 和 SES（S 为十六分音符）。休止符、长音和跨拍事件断开分组；单个音符保留符尾，不跨小节。`RhythmScoreLayout.ts` 按音乐时值生成小节内分组，渲染层在排版前创建 VexFlow Beam、排版后绘制。每个音符仍独立播放、判定与高亮，共用连梁保持黑色；数据模型和时间线不变。

## 回调延迟、暂停与停止

动画帧只是检查机会，不是时钟。页面卡顿或隐藏期间画面和漏拍反馈可能延迟；恢复后直接定位到正确位置并补齐漏拍，不逐拍补播。音频暂停后音频时钟停止推进，检查循环也不会提前判漏拍。

停止时清除本轮时钟，取消 RAF 循环，并通过 `stopScheduledSounds()` 停止已保存的预备拍、试听和用户击拍声源；重新开始清理旧声音并建立新的时钟和游标。试听与听写声音在音符终点归零，击拍短音在发声 200ms 后归零，结束后自行断开节点并从列表移除，不等待整段采样的长尾。击拍短音可能略跨过练习结束时刻；组件卸载时取消循环、停止全部声音并关闭音频上下文。

统一时钟不等于完成设备延迟校准：音频输出延迟、键盘事件到达 JavaScript 的延迟仍然存在。当前 UI 也受动画帧频率限制。

## 练习结果

`summarizePractice(targetCount, timingEvents)` 是纯统计函数，接收同一轮自然结束后的完整记录：每个目标恰好对应一次 hit 或 miss。它返回目标数、命中数、漏敲数、误敲数与 passed；perfect / early / late 均计入命中。通过条件是所有目标命中、没有漏敲且没有误敲。零目标且没有误敲也通过。

`RhythmTrainer` 仅在击拍模式的 finished 阶段，从当前判定记录直接计算结果，显示“通过 / 未通过”，不增加结果 state 或完成回调。结束帧先补齐漏拍，再更新阶段；统计在状态更新后的渲染中进行，不在 setTimingEvents 后立即读取旧记录。自然结束保留谱面反馈；手动停止和试听不显示结果，成功重新开始或配置切换导致组件重建后旧结果消失。

十六分音符在 BPM 120 下间隔 125ms，相邻命中窗口会重叠，仍按最靠前待匹配目标判定。新增音符没有修改窗口或难度标准；测试覆盖 60、120、240 BPM 的时间线与顺序命中。


## 小三连与整数音乐时值

小节使用 `elements`，元素可以是普通 `RhythmEvent` 或 `{ kind: "triplet", notes: [...] }`。三连音组恰好包含三个无附点八分音符，共占一拍；允许从非拍头位置开始并跨越拍界，但整组不能超出小节。不支持组内休止符、其他时值或嵌套。三连音始终独立连梁，不与前后普通音符相连。预设题目仍可采用拍头开始的简单节奏，不限制模型和编辑器的输入位置。

`expandRhythmElements()` 统一输出独立事件、小节内起点 tick、时长 tick 和三连音组下标。每四分拍 24 ticks，八分 12、十六分 6、附点十六分 9、三连音每音 8；每小节校验总和为 96。小节和事件音乐位置使用整数累计，再按 `绝对 tick / 24 * (60000 / BPM)` 独立换算起点和终点，不累计近似的三分之一拍毫秒数。

`eventIndex` 仍是展开后包含休止符的全局事件编号。三连音的三个音符分别发声、高亮和判定；判定窗口及统计不变。VexFlow Tuplet 在排版前关联三个八分音符，按 3:2 改变内部时值并显示“3”，每组独立连梁。内部 24 ticks 不是 VexFlow 的时间单位。
