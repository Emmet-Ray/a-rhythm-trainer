# 音频时钟与击拍判定

本文解释跨模块的时间约定和容易误改的判定规则。具体接口与参数以 [RhythmAudio](src/rhythm/RhythmAudio.ts)、[RhythmTiming](src/rhythm/RhythmTiming.ts) 的契约注释为准；状态归属和记录粒度见 [架构说明](../docs/ARCHITECTURE.md)。

## 时间线、时钟与单位

时间线描述谱面在给定 BPM 下应发生什么；每轮时钟把它映射到一次实际播放。
声音排程和练习进度使用 `AudioContext.currentTime`，RAF 只读取位置、补画面反馈和检查结束。卡顿后直接定位到当前时间，不逐拍补播。

正式起点为相对 `0ms`，预备拍为负值；业务时间使用相对毫秒，音频排程使用绝对秒数，转换封装在音频模块。
开始前等待 AudioContext 恢复以及采样加载／解码，之后建立时钟；等待时间不计入练习。

```text
正式起点秒数 = 当前音频秒数 + (调度余量毫秒 + 预备拍总毫秒) / 1000
当前相对毫秒 = (当前音频秒数 - 正式起点秒数) × 1000
排程绝对秒数 = 正式起点秒数 + 事件相对毫秒 / 1000
```

预备拍默认一小节。60 BPM、四拍预备拍和 100ms 调度余量下，时钟创建时为 -4100ms，预备拍位于 -4000、-3000、-2000、-1000ms。
调度余量只为提前排程留时间，不增加音符时值或判定误差。

## 音乐时值与谱面位置

BPM 当前以四分音符为一拍。音乐位置以整数 tick 累计，再逐点换算为毫秒，避免三连音近似值不断累加。
每四分拍 24 ticks；每个完整 4/4 小节为 96 ticks。小三连的三个无附点八分音符各占 8 ticks，可跨拍界但不能跨小节。
模型与展开规则见 [RhythmModel](src/rhythm/RhythmModel.ts)；扩展节奏范围还需同步前后端校验、输入、播放和记谱。

小节间不重置时间、不增加预备拍。`eventIndex` 是展开后的全局事件下标，包含休止符；休止符占时间但不生成敲击目标。
长音只在起点生成一个目标，不要求长按，判定窗口也不随音符时值扩大。

谱面排版坐标用于显示，不参与判定。误敲位置按小节的时间／位置锚点插值，不能假设 VexFlow 排版是等比例时间轴。
相关映射见 [RhythmScoreLayout](src/rhythm/notation/RhythmScoreLayout.ts)。

## 输入发生时间与回调延迟

`inputTimeMs(event.timeStamp)` 在同一连续运行区间内扣除事件分发等待，得到敲击发生时的相对时间。
它不使用回调处理时间兜底；非有限、未来、早于当前输入区间的事件被忽略。
音频挂起／恢复或检测到时钟不连续时建立新的输入区间，避免将暂停期间的输入反推到当前轮。
动画只用 `readTimeMs()` 纯读时间，不调用会更新输入采样的接口。

RAF 先显示漏拍、输入后到达时，不能让旧漏拍永久阻止命中。判定保存原始敲击时间，每次输入按发生顺序重算，再补齐截至当前的漏拍；无新输入时画面只增量补漏。
重算只改变判定，不重播历史声音；相同时间戳仍可能代表不同敲击，不自动去重。

音频暂停时进度停止推进。扣除分发等待不等于硬件延迟校准：音频输出、浏览器时间精度以及实际声音响应仍受设备和主线程影响。

## 匹配与结束

- 命中窗口为 `[目标起点 − hitMs, 目标起点 + hitMs)`；完美范围包含正负边界。
- 窗口重叠时匹配最近的待判定目标，等距优先较早目标；被跳过的旧目标记漏拍。
- 没有候选时记误敲，不消耗尚未过期的目标。“不回头补敲”按事件发生顺序理解。
- 判定窗口不随 BPM 缩放，每轮开始前固定独立快照；具体档位见 [tappingPrecision](src/settings/tappingPrecision.ts)。
- 整轮终点取谱面总时长与最后一个命中窗口关闭时间的较晚值，避免截断末尾休止或允许的晚击。

例如标准窗口下，120 BPM 连续八分音符起点为 0、250ms：140ms 的敲击更接近第二音，命中第二音并把第一音记漏拍；125ms 等距时优先第一音。

自然结束保留本轮时钟和输入，终点前发生、结束后才送达的输入可修正同一次结果，不补响。
主动停止立即废弃旧时钟；正式开始后停止结算未通过，准备／预备拍期间停止不产生尝试。
新一轮、换题、改速或卸载作废旧异步启动和排程，不恢复旧轮音频；迟到事件不能进入新轮。
通过条件为所有目标命中且没有误敲，命中的 early／late 也算命中。

## 声音与节拍器

试听和听写按音符起止排程；击拍反馈立即播放固定长度短音，不依赖谱面时值或命中误差。
重算不发声，结束后到达的旧输入只修正结果。采样不循环或拉伸来伪造延音。

草稿播放按完整小节留时，未填满部分保持静默，不向答案补入休止符；全空草稿不能启动。
每次启动固定当时的时间线，播放期间编辑不改变已安排声音，下次播放才使用新内容。

预备拍始终发声，正式节拍器可独立开关；重新开启接上后续原定拍点，不补响或重置拍位。
机械摆杆只读取同一时钟，掉帧后恢复当前拍位；减少动态效果时停止摆动，保留声音与开关。
采样截取与淡入淡出参数集中在音频模块，替换素材需要重新试听；当前节拍器素材的来源链接与具体许可仍待补充。

## 验证

在 `frontend/` 执行：

```sh
node --test tests/rhythm-time.test.mjs tests/rhythm-audio.test.mjs tests/tapping-precision.test.mjs
```

浏览器／实际试听重点：回调晚到时修正同轮、自然结束后不补响、停止后拒绝旧输入、暂停恢复不跨段判定，以及调速或卸载后旧声音不复活。
Node 模拟时钟测试不能证明真实设备延迟和声音效果；浏览器环境准备见 [前端说明](README.md#浏览器回归)。
