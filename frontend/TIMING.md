# 练习里的时间怎么算

练习进度和声音排程以 `AudioContext.currentTime` 为准。键盘输入通过 `PracticeClock.inputTimeMs(event.timeStamp)` 映射到同一时间轴；浏览器单调时钟仅用于扣除事件分发等待，不驱动练习进度。`App.tsx` 负责页面路由和公共导航，`PresetPracticePage.tsx` 内的私有组件 `PresetExercisePage` 根据题目地址提供练习参数。

## 先分清两件事

### 可开关节拍器

节拍器素材为 `public/assets/audio/metronome.mp3`，保留用户提供的原文件（约 0.816 秒，24 kHz 双声道）。能量检测显示主要起音约在 46ms，播放从 44ms 开始取 200ms，1ms 淡入、最后 20ms 淡出；强拍增益 0.7，普通拍 0.45，不改变播放速率。该截取参数仅针对当前素材，替换文件需重新检查。素材由用户提供并声明免费使用，来源链接及具体许可尚待补充。

`prepareMetronomeSound()` 与钢琴采样并行准备，各自按 AudioContext 缓存与去重，失败允许重试。两种练习都等待采样就绪后才建立时钟，避免首次加载推迟实际起音；关闭正式节拍器仍会加载该素材，供预备拍使用。

练习页的“节拍器”默认开启，控制正式阶段的节拍器声部，预备拍始终保留。`metronomeEnabled` 作为独立 prop 传给击拍与听写组件，不参与时间线或播放器 key；切换不清空击拍记录、听写草稿或判定结果。当前页面内修改 BPM 保留开关选择，换题重置为开启。

`rhythm/RhythmAudio.createMetronome()` 使用同一 `PracticeClock`，提前安排正式起点至谱子终点之前的四分拍，每小节第一拍重音。它复用预备拍的 metronome.mp3 采样音色，但使用独立声源列表，钢琴声不受开关影响。关闭时取消本声部，重新开启时只安排下一个原定拍点及之后的声音，不立即补响、不重置拍位。休止符、长音和空白答案小节也持续计拍；谱子结束处不额外打一拍，也不延伸到击拍判定的额外等待窗口。

停止、切换播放入口、修改 BPM、换题、离开页面和本轮结束时释放该声部。拍点由音频时钟排程，不由 RAF 触发；RAF 仍只处理界面和结束收尾。这里没有空闲时独立运行的节拍器。

击拍谱面反馈统一为圆形：命中是绿色实心圆，漏拍是红色空心圆，二者位于对应音符下方；误敲是红色实心圆，按实际敲击时间定位。三种标记外径一致，只改变绘制样式，不影响判定、时间映射或结果统计。

击拍和听写共用 `rhythm/notation/RhythmNotation.ts` 的单线节奏记谱规则：只显示中线，行首使用打击乐谱号，普通音符统一向上。VexFlow 内部仍保留五线坐标，以维持休止符、拍号和附点定位；这只是显示方式，不增加音高数据或改变时值。击拍反馈以可见中线下方 32px 为基准，随谱面统一缩放。

1. **时间线**：谱子决定“应该什么时候发生什么”，与点击开始的时刻无关。
2. **时钟**：本轮练习“现在进行到哪里了”，点击开始后才建立。

`rhythm/RhythmTiming.ts` 的 `createExerciseTimeline()` 根据配置生成时间线。`rhythm/RhythmAudio.ts` 的 `createPracticeClock()` 建立本轮时钟。`practice/RhythmTrainer.tsx` 用时钟读数查询时间线。

## 训练组件参数

预设页与随机页共用 `PracticeWorkspace`，由它选择训练方式，内部的 `PracticeSettings` 统一管理 BPM 与节拍器开关，页面负责标题、导航及题目来源。预设页使用题目 ID 作为工作区 key；随机页始终显示工作区，以 `exercise: null` 表示尚未生成：击拍显示空谱，听写显示“请先生成题目”和“当前小节：—”，依赖题目的操作禁用，但设置可调整。不使用伪造的空练习作为标准答案。

随机页只在提交生成表单时调用 `generateRandomExercise()`，成功后递增生成序号作为 `exerciseKey` 传入，仅重建内部训练组件。即使生成内容相同，也会取消旧播放、清空记录/草稿，但保留 BPM（包括未应用的输入）和节拍器设置。修改主题或小节数不换题、不停止播放；配置无效或生成失败同样保留当前训练。生成配置也不重置；修改 BPM 或节拍器不触发生成。切换模式、离开或刷新随机页后回到未生成、仅选基础音符、两小节和默认播放设置状态。

```tsx
<RhythmTrainer exercise={exercise} bpm={60} />
```

`exercise` 和 `bpm` 必传；`countInBeatCount` 默认取拍号中的拍数，当前 4/4 为四拍（一个小节），显式指定非负整数可覆盖，0 表示关闭预备拍。`timingWindows` 可显式覆盖窗口；未传时，击拍使用设置页选择的精度，试听保持原标准窗口 `{ perfectMs: 50, hitMs: 150 }`。每轮开始、异步音频准备之前读取独立快照，之后的偏好或窗口 prop 变化不影响当前轮次及结束后的迟到输入重算。模式、播放状态、判定记录和音频资源由训练组件内部管理。

击拍精度参数集中在 `settings/tappingPrecision.ts`，不根据 BPM 缩放：

| 档位 | 完美容差 perfectMs | 命中容差 hitMs |
| --- | --- | --- |
| 宽松 | 80 | 200 |
| 标准（默认） | 50 | 150 |
| 严格 | 30 | 100 |

完美范围含正负边界，命中窗口仍为 `[目标起点 − hitMs, 目标起点 + hitMs)`。这些是项目的初始体验参数，不是行业统一标准。窗口重叠时仍匹配最近的待判定目标，调宽窗口不保证较远目标优先命中。偏好由浏览器保存，设置页不允许直接填写毫秒；预设、随机、本地及账号自定义击拍都经由同一训练组件读取，听写判题不接入。

击拍、试听与听写共用 `createCountInTimeline()`，由同一份预备拍总时长与负时间偏移驱动时钟和声音排程。60 BPM 的默认 4/4 预备拍为 `[-4000, -3000, -2000, -1000]ms`，正式题目仍从 0ms 开始；120 BPM 时这些时长减半。当前节奏模型仍只支持 4/4，尚未开放 2/4、3/4 或复合拍号。

组件通过 `useMemo` 根据练习、BPM、预备拍数和判定窗口生成时间线。判定窗口按 `perfectMs`、`hitMs` 两个数值建立依赖，因此传入等值新对象不会重建时间线。练习内容不变时，父组件应保持 `exercise` 引用稳定；修改内容时应创建新对象，不要原地修改。

`exercises/presetExercises.ts` 按“主题 → 模式 → 题目”组织十三个主题的 58 道击拍题目（分别为 3、6、5、5、4、4、4、5、4、4、4、5、5 道，包含 2、3、4、5、6、8 小节的练习）。每个主题的听写和几何游戏题库独立维护。练习库在主题内选择模式并列出其题目；`PresetExercisePage` 从 `/preset/:questionId` 查找题目及所属模式，按模式进入共用的 PracticeWorkspace，并提供 BPM 滑块与数值输入（40–240 的整数）。拖动松手、数值输入失焦或回车后生效，不再提供“应用速度”按钮。预备拍数使用组件默认值，击拍窗口按所选精度取值。

`PresetExercisePage` 使用题目 ID 重建配置区域；工作区只在换题时重建击拍组件，不再把 BPM 放进 `key`。`RhythmTrainer` 在题目、BPM 或预备拍数真正改变时原地清空本轮状态，并在布局 effect 的清理中废弃旧时钟、停止声音、关闭音频上下文、作废异步启动；RAF 随运行状态重置取消，不自动开始新一轮。渲染子级前清空旧判定，避免旧记录被新时间线解释。应用相同 BPM 或只编辑草稿不打断。返回或离开练习页仍卸载训练；刷新、换题及重新进入页面恢复默认 60 BPM，不保存进行中的一轮。

界面不重复显示生效 BPM，也不再显示“未应用”。数值框与滑块共用草稿；草稿为空、非整数或越界时，滑块回到原生效值，失焦或回车显示错误并保留当前轮。闲置状态不显示占位反馈；播放期间显示预备拍或即时判定，击拍结束只显示结果并保留谱面标记；试听显示进行中/结束状态，不生成练习结果。这些显示规则不改变时间线或判定逻辑。

`RhythmScore` 将静态排版与动态反馈分开：只有题目内容、拍号或容器宽度变化才重新绘制基础 SVG。BPM 变化只关联新的时间锚点；试听高亮和判定标记单独更新，清空反馈不移除谱面。`createTimingFeedbackLayout()` 将实际排版坐标与当前时间线关联，误敲仍按时间插值定位，判定算法不变。


事件支持 `dots?: 0 | 1`：省略或 0 为无附点，1 为单附点，音符和休止符共用。`rhythmEventToDurationInQuarterNotes()` 统一计算完整事件时值（单附点为基本时值 × 1.5），普通事件经它换算后转为整数 tick，再由统一展开结果供时间线和连梁分组使用。VexFlow 的 `dots` 设置内部时值，`Dot` modifier 绘制附点；声音和判定不增加专用分支。十六分音符使用 `noteValue: "sixteenth"`，基本时值为 0.25 拍，对应休止符与单附点也支持。附点全音符虽然可计算为六拍，但不能放进当前四拍小节。

## 统一零点与单位

练习模型使用 `measures: { elements: RhythmElement[] }[]` 显式表达小节，小节不再使用 events 字段。小节数由内容决定，整份练习共用 4/4 拍号；约定每小节填满四拍，事件不跨小节。生成时间线前调用 `validateRhythmExercise()`，拒绝欠拍、超拍和空小节，错误包含小节编号与实际拍数；不自动补拍或拆分。零小节仍可表示空练习，全小节休止必须显式录入休止符。这是类型化内容的校验，不是任意外部 JSON 的结构解析。

时间线按小节顺序连续累计，不在小节边界重置时钟或添加预备拍。`eventIndex` 是包含休止符的全局事件下标，不是小节内编号。时间线额外提供 `measures`（startOffsetMs、endOffsetMs、firstEventIndex）和 `eventStartOffsetsMs`，渲染层不重复计算 BPM 或小节时间。

例如 BPM 60，两小节分别为两个二分音符、一个全音符：目标起点为 [0, 2000, 4000]ms，事件终点为 [2000, 4000, 8000]ms；只有整份练习结束才统计结果。

正式练习开始是 `0ms`。预备拍在负数区间；练习进行中是非负数。业务层全部用相对毫秒，音频 API 的绝对秒数封装在 `rhythm/RhythmAudio.ts`。

以下为显式设置三拍预备拍的示例（不是当前默认值），假设 BPM 为 60、100ms 调度缓冲：

| 相对正式练习起点 | 事件 |
| --- | --- |
| -3100ms | 音频准备完成、创建本轮时钟，画面显示“准备中” |
| -3000ms | 第一声预备拍，显示预备拍 1 |
| -2000ms | 第二声预备拍，显示预备拍 2 |
| -1000ms | 第三声预备拍，显示预备拍 3 |
| 0ms | 正式练习开始，第一个音符起点 |
| 150ms | 击拍模式下，若第一拍未命中，允许判定 miss |

100ms 是给音频提前排程的余量，不属于预备拍或音符时值。等待 `resume()` 和 `prepareTapSound()`（钢琴采样下载/解码）都完成后，才读取音频时间建立时钟；这些等待不计入练习。

## 同一个时钟的时间接口

```ts
clock.nowMs()                 // 本轮现在进行到哪一毫秒
clock.audioTimeAt(offsetMs)   // 这个相对时刻对应音频时间轴上的第几秒
clock.inputTimeMs(timeStamp)  // 输入发生的相对毫秒；无效或跨段输入为 null
```

转换公式只在 `rhythm/RhythmAudio.ts` 出现：

```text
正式起点秒数 = 当前音频秒数 + (缓冲毫秒 + 预备拍总毫秒) / 1000
当前相对毫秒 = (当前音频秒数 - 正式起点秒数) × 1000
排程绝对秒数 = 正式起点秒数 + 事件相对毫秒 / 1000
```

例如创建时音频时间是 10 秒，正式起点就是 13.1 秒。第一声预备拍排在 10.1 秒。音频时间走到 14.15 秒时，`nowMs()` 约为 1050。

输入映射在同一连续运行区间内使用“当前音频相对时间 −（当前浏览器时间 − 事件创建时间）”。因此处理回调晚到 80ms，不会直接给敲击误差加上 80ms。兼容旧浏览器的 epoch 毫秒时间戳；非有限、未来、早于本轮创建的时间戳直接忽略，不用回调处理时间兜底。`event.timeStamp` 是浏览器创建事件的时间，不保证等于硬件按下时刻。

音频 `statechange` 会调用 `resetInputTime()` 建立新的输入区间。挂起期间及恢复前的旧输入不再接受，避免跨暂停反推；相邻采样中浏览器与音频时间增量相差超过 50ms，也保守地换段，以防状态通知尚未到达。这个容差用于检测时钟不连续，**不是新增判定窗口或延迟补偿值**。切换边界附近可能丢弃排队输入；音频时钟量化、隐私降精度及硬件延迟仍限制精度，不能保证所有平台逐毫秒准确。

## 谱子如何变成时间线

当前 BPM 以四分音符为单位：一拍毫秒数 = `60000 / BPM`。

事件时长 = 一拍毫秒数 × 四分音符单位的时值。全音符为 4，二分音符为 2，四分音符为 1，八分音符为 0.5，十六分音符为 0.25；单附点再乘以 1.5。依次累加得到每个事件的起点和终点；对应休止符也参与累计，但不生成敲击目标。长音符只在起点生成一个目标，不要求长按；试听与听写在目标音符终点收音，用户击拍则播放固定长度的短音。BPM 60 的全音符目标在 0ms，事件结束在 4000ms；中途多敲属于误敲，命中窗口不会随音符时长扩大。

### 新增音符时修改哪些地方

- `rhythm/RhythmModel.ts`：扩展 NoteValue，以及到四分音符单位时值的换算。
- `rhythm/notation/RhythmScore.tsx`：增加 VexFlow duration 映射；whole → w、half → h、quarter → q、eighth → 8、sixteenth → 16，休止符追加 r。保持乐谱库编码位于显示层，不放入核心模型。
- `exercises/presetExercises.ts`：按需增加预设练习，不是底层支持的必要步骤。
- 测试：验证时间线、目标数量、混合时值、休止符、BPM 缩放及结束边界；谱面另做渲染验证。

新增普通时值无需改动音频时钟、声音排程、匹配、漏拍与结果统计：它们使用展开后的偏移时间和目标记录。试听高亮也沿用事件终点。这一约定不自动覆盖连音线、复附点或其他连音组等额外记谱语义。

以时间测试中的单小节 `Q Q Q EE` 在 BPM 60 下为例（不是当前预设题）：

| 音符 | 起点 ms | 终点 ms | 命中窗口 ms |
| --- | --- | --- | --- |
| 四分 | 0 | 1000 | [-150, 150) |
| 四分 | 1000 | 2000 | [850, 1150) |
| 四分 | 2000 | 3000 | [1850, 2150) |
| 八分 | 3000 | 3500 | [2850, 3150) |
| 八分 | 3500 | 4000 | [3350, 3650) |

试听模式下，高亮的逻辑切换时刻是音符起点；击拍模式下不显示音符高亮，未命中目标从窗口关闭时起可以判为 miss。以当前窗口设置计算，漏拍的逻辑时刻比目标起点晚 150ms，实际标记会在后续画面更新中呈现。

两种模式共用结束时间公式：取“谱子总时长”和“最后一个目标窗口关闭时间”中较晚的那个。击拍按本轮精度窗口计算，试听保持标准窗口（显式传入 `timingWindows` 时按覆盖值），两者的结束等待可能不同，但音符起止和声音排程不变。击拍模式结束前先收齐未判定的过期目标，不需要人为追加 1ms 来竞争定时器顺序。当前预设在 BPM 60、默认窗口下，按小节数分别在 8000、12000、16000、20000、24000、32000ms 结束（不含预备拍）；末尾音符时值短于窗口时，额外保留对应的判定等待。

## 击拍与试听模式

`mode` 表示本轮用途（practice / listen），`phase` 表示运行阶段。模式在开始时确定，播放中另一个模式按钮禁用，当前按钮用于停止；等待音频恢复时两个按钮都禁用。

| 行为 | 击拍 practice | 试听 listen |
| --- | --- | --- |
| 预备拍声音与倒数 | 有 | 有 |
| 自动播放音符 | 无 | 有，休止符不响 |
| 当前音符高亮 | 无 | 有 |
| 空格击拍音与判定 | 有 | 无 |
| 自动漏拍与判定文字 | 有 | 无 |

两种模式共用时间线、本轮时钟和 RAF 循环。每次开始清空上一轮的判定记录。模式不改变既有匹配规则。

## 听写题目与草稿播放

听写草稿与选中小节仍由 `practice/RhythmDictation.tsx` 持有。`practice/RhythmEditor.tsx` 通过回调提交单个小节的新元素，并复用 `rhythm/notation/RhythmDraftScore.tsx` 绘谱；编辑器不依赖音频或判题。选中小节回调仍更新原来的播放器 key，编辑回调只更新草稿与对应判定，不重建播放器。验证时通过编辑器的 `clearMessage()` 清除输入提示，不改变草稿、选择或谱面布局。空态文案由调用方提供，编辑器本身不依赖随机题目生成流程。

`practice/RhythmPlayback.tsx` 统一管理一个音频上下文与声源列表；听写传入“播放题目”和“播放我的答案”两个候选，自定义传入“试听”一个候选。切换入口先取消旧声音和未完成的加载请求。同一入口再次点击停止，换题、修改生效 BPM 或卸载时清理播放器。各入口 ID 在一次播放器挂载期间应稳定、唯一。

听写、击拍和自定义共用 `PracticeSettings` 的调速控件：默认 60，接受 40–240 的整数。乌龟／兔子分别提示慢／快；滑块拖动时只更新显示，松手生效，指针捕获保证移出轨道后松手也可提交。触摸滚动引发取消或失去捕获时放弃拖动草稿，恢复原速度。滑块键盘方向键、Home／End 及辅助技术操作直接生效；数值输入失焦或按 Enter 生效，不增加防抖计时器或自动播放。

只编辑数字、尚未松手的拖动、非法输入或提交相同 BPM 不停止播放。滑块由窗口级 pointerup 统一提交最终草稿，移出轨道松手同样生效；不接管原生 range 的指针捕获，也不把控件失焦／失去捕获当成取消。滑块区域使用 touch-action: none，避免斜向拖动被页面滚动抢走；其他区域仍可滚动。Escape、pointercancel 或窗口失焦恢复拖动前速度。生效 BPM 真正改变后停止当前轮／播放而不自动重启；击拍原地清除本轮反馈并保留谱面。听写仅通过内部播放器的 key 取消旧播放和异步启动，不重建答题组件，因此草稿、验证结果、选中小节、播放范围和参考答案展开状态均保留。换题通过外层题目 key 重置整个练习页和 BPM。

“整题／当前小节”范围由两个播放入口共用，默认整题。当前小节模式只传入选中的题目小节与答案小节，时间线从该小节的 0ms 开始，不播放前面的小节，仍使用一小节预备拍和完整小节时长。答案按钮按所选范围是否为空决定是否禁用。切换范围或选中小节（整题模式下也包括）时通过 key 重建播放器，取消旧声音及未完成请求，但不重置草稿、范围选择或验证结果。播放器重建也会关闭旧音频上下文，新播放重新准备声音。

题目和草稿均由 `rhythm/RhythmTiming.ts` 中的 `createRhythmPlaybackTimeline()` 按当前 BPM 展开音乐时值，使用相同的一小节预备拍与钢琴音色，不使用击拍判定窗口。草稿允许未填满：每小节仍占完整四拍，未填写部分、空白小节及末尾空白小节保持静默，不向答案数组补休止符。全空草稿禁止启动答案播放；只有休止符的草稿可以播放静默时值。

每次点击固定一份起止时间排程。播放时允许继续编辑，已安排的声音不随草稿变化，下次播放使用最新草稿；播放不清空答案、不改变判题结果、不高亮草稿。即使播放中删空答案，停止按钮仍可用。

## RhythmTrainer 每次做什么

自定义编辑页复用上述公共播放器，key 由生效 BPM 和小节数量组成。因此增减小节或应用新速度会取消排程和异步启动，但不会重建公共设置或草稿编辑器；仅修改音符、名称或选中位置不影响已开始的整谱播放。自定义不使用击拍流程，也不引入听写判定。

自定义保存成功后跳转回题目列表，播放器卸载并取消旧声音和未完成的异步启动。保存失败不跳转，也不主动停止当前试听，草稿和设置保留。持久化只记录题目内容，不保存 BPM、节拍器或播放状态。

预备拍声音提前用 `audioTimeAt()` 和 `scheduleCountIn()` 安排，使用 metronome.mp3 单次采样，强弱拍只改变增益，不改变音高。试听模式额外遍历 `timeline.targetTaps`，通过 `scheduleTapSound()` 在每个音符起点安排钢琴采样，音色与用户空格击拍和听写播放一致。休止符不生成目标，所以不发声，但仍占用时长。预备拍、试听音和用户击拍音都保存在 `scheduledSourcesRef` 中，停止或卸载时一起取消。

击拍模式在按键通过输入检查后、重算判定前调用 `playTapSound()`，内部调用同一个 `scheduleTapSound()`，使用当时的音频时间立即排程，不添加 100ms 调度余量，也不等待下载或解码。命中与误敲使用相同的 200ms 钢琴短音。自然结束后送达的旧输入只修正结果，不补响。采样按 AudioContext 缓存，加载失败可重试。

钢琴参数集中在 `rhythm/RhythmAudio.ts`：从原始采样 10ms 处开始，增益 0.7，起音淡入最多 2ms。`scheduleTapSound()` 接收音频绝对起止秒数，在指定终点前淡出并归零，淡出长度取 80ms 与实际发声长度的四分之一中较小值。试听与听写传入目标起点和 `eventEndOffsetsMs[target.eventIndex]` 对应的终点；用户敲击通过检查后，命中与误敲均调用 `playTapSound()` 立即播放固定 200ms 的同音色短音，再重算判定，短音包含末尾 50ms 淡出。击拍反馈不接收目标终点，不随 BPM、音符时值或早晚误差改变长度；长度统一由 `TAP_SOUND_SECONDS` 控制。若素材先播完则自然结束，不循环或拉伸采样。原始 MP3 和音符时间线保持不变。

页面只有一条 `requestAnimationFrame` 更新循环：

1. 读取一次 `clock.nowMs()`。
2. `recordExpiredTargets()` 在击拍模式补齐截至此刻的暂定漏拍并推进画面游标；试听模式直接返回。
3. `getPlaybackPosition()` 根据此刻定位预备拍或音符。
4. 显示位置变化才更新 React 状态；到终点则结束本轮。

输入框、下拉框、按钮和可编辑区域内的空格保留控件自己的行为，不作为击拍。其他位置按空格时先确认本轮时钟存在、音频处于运行状态，并忽略长按产生的重复事件。试听模式阻止空格的默认行为后直接返回，不发出击拍音或产生判定。击拍模式通过 `clock.inputTimeMs(event.timeStamp)` 取得敲击时间，以事件发生时刻而非回调处理时刻检查整轮终点。正式开始前仍只接受第一个目标窗口内的首次提前命中。

通过这些检查后，先立即安排一次击拍音，再保存 `tapOffsetMs` 并调用 `judgePractice()`。它按事件时间排序原始输入，从头执行现有 `evaluateTap()`，最后补齐当前时刻的漏拍，整体替换画面记录。原始输入存在 ref 中，同步写入，不依赖 React 是否已完成渲染。RAF 的游标只是补漏缓存，不能成为下一次敲击的匹配起点。这样 RAF 先画出漏拍、输入后到达也不会永久丢失命中；乱序到达与按发生顺序到达的最终判定一致。重复时间戳仍代表不同敲击，不自动去重。

只有输入到达时重算整轮；没有新输入时 RAF 仍只增量补漏，不每帧排序全部记录。重算函数不接触音频，无论结果修正多少条，都不会再次播放历史敲击。没有加入固定等待窗口，也没有为了等待输入而推迟结束画面。

## 当前匹配规则

`evaluateTap()` 接收按时间升序排列的目标与当前游标，先补齐过期目标，再选择命中窗口内时间误差最小的待判定目标；等距优先较早目标。命中时把跳过的旧目标记为漏拍，不允许回头补敲；没有候选时记为误敲，不消耗尚未过期的目标。窗口仍采用左闭右开区间，绝对误差不超过 `perfectMs` 为 perfect，其余负误差为 early，正误差为 late。

`evaluateTap()` 的返回值 `{ events, nextTargetIndex }` 包含本次全部漏拍、最后一条命中或误敲，以及新游标。`judgePractice()` 按时间顺序调用它重建整轮记录，不改变最近匹配、等距优先及跳过目标的规则。“不回头补敲”指事件发生顺序，不能把事件晚送达误当成用户晚敲。标准窗口保持 `perfectMs: 50`、`hitMs: 150`，所有精度档位均不随 BPM 改变。

相邻窗口可以重叠。例如 BPM 120 的连续八分音符起点为 0ms、250ms，窗口分别为 [-150, 150)、[100, 400)。在 140ms 敲击时，第二个目标误差为 -110ms，比第一个目标的 +140ms 更近，因此命中第二个目标并判为 early；若第一个目标尚未判定，同时记为漏拍。在 125ms 敲击时两者等距，优先第一个目标。

早于下一个目标窗口的敲击，以及目标全部判定完毕后、本轮结束前的敲击，统一返回 `{ kind: "wrongTap", tapOffsetMs }`。误敲不区分原因，不保存参考目标或误差，不推进游标；每次有效误敲分别记录，文字显示“误敲”，谱面按敲击时间显示红色实心圆。例如最后一个目标在 3500ms 已命中，在 3750ms 再敲一次，距离整轮 4000ms 的终点尚有时间，所以会发声并新增误敲记录。最后目标漏拍后继续敲击也采用同一规则。

判定函数不负责判断整轮是否结束；调用者过滤无效输入时间后才调用它。到达目标窗口右边界时，该目标先结算为漏拍，再尝试匹配后续目标；若没有候选，本次记录以误敲结束，不再返回 null。即使动画帧尚未检查过期目标，敲击路径也能独立完成结算。

## 多小节谱面与反馈位置

`RhythmScore` 接收整份时间线，每小节单独创建 Stave，按容器宽度以完整小节换行。每行显示谱号，仅第一小节显示拍号，最后一小节使用终止线；极窄容器统一缩放谱面与反馈，暂不跟随滚动。高亮及 hit/miss 标记按全局事件下标关联对应音符。

每小节渲染后收集所有事件（含休止符）的时间和横坐标，再添加小节结束锚点。`rhythm/notation/RhythmScoreLayout.ts` 中的纯函数先按误敲时间选择小节，再在该小节锚点之间插值计算 X，Y 使用该小节所在行的反馈基线；边界属于后一小节，首尾越界限制在谱面范围内。单个全音符或全休止符也有起止两个锚点，因此不同时间的误敲能分布到不同位置。这是谱面显示映射，不参与判定，也不表示 VexFlow 的排版是严格等比例时间轴。


同一四分拍内的连续八分、十六分音符（含单附点）可混合连梁，支持 EE、SSSS、ESS、SSE、E.S 和 SES（S 为十六分音符）。休止符、长音和跨拍事件断开分组；单个音符保留符尾，不跨小节。`rhythm/notation/RhythmScoreLayout.ts` 按音乐时值生成小节内分组，渲染层在排版前创建 VexFlow Beam、排版后绘制。每个音符仍独立播放、判定与高亮，共用连梁保持黑色；数据模型和时间线不变。

## 回调延迟、暂停与停止

动画帧只是检查机会，不是时钟。页面卡顿或隐藏期间画面和漏拍反馈可能延迟；恢复后直接定位到正确位置并补齐漏拍，不逐拍补播。音频暂停后音频时钟停止推进，检查循环也不会提前判漏拍。

停止时清除本轮时钟，取消 RAF 循环，并通过 `stopScheduledSounds()` 停止已保存的预备拍、试听和用户击拍声源；重新开始清理旧声音并建立新的时钟和游标。试听与听写声音在音符终点归零，击拍短音在发声 200ms 后归零，结束后自行断开节点并从列表移除，不等待整段采样的长尾。击拍短音可能略跨过练习结束时刻；组件卸载时取消循环、停止全部声音并关闭音频上下文。

自然结束保留本轮时钟与原始输入：发生在终点前、结束后才送达的按键可以修正结果，但不补响、不重新启动节拍器。终点之后实际敲击无效。手动停止、新一轮启动（含异步准备期间）、换题和卸载则立即失效旧时钟；新时钟拒绝创建前的时间戳，防止排队事件串轮。

统一时钟不等于完成设备延迟校准：音频输出延迟仍然存在。事件分发等待现在可以从判定时间中扣除，但主线程阻塞时，声音与 UI 仍需等待处理机会，不可能回到过去发声。当前 UI 也受动画帧频率限制。

## 练习结果

`summarizePractice(targetCount, timingEvents)` 是纯统计函数，接收同一轮自然结束后的完整记录：每个目标恰好对应一次 hit 或 miss。它返回目标数、命中数、漏敲数、误敲数与 passed；perfect / early / late 均计入命中。通过条件是所有目标命中、没有漏敲且没有误敲。零目标且没有误敲也通过。

`RhythmTrainer` 仅在击拍模式的 finished 阶段，从当前判定记录直接计算结果，显示“通过 / 未通过”，不增加结果 state 或完成回调。结束帧先补齐漏拍，再更新阶段；统计在状态更新后的渲染中进行，不在 setTimingEvents 后立即读取旧记录。自然结束保留谱面反馈；手动停止和试听不显示结果，成功重新开始或配置变化重置本轮后旧结果消失。

## 验证

在 frontend 目录执行 `npm test`，运行 `package.json` 明确列出的全部测试文件。时间回归也可单独执行 `node --test tests/rhythm-time.test.mjs`。

测试使用 Node 内置测试工具，并复用 Vite 加载 TypeScript 模块，不启动 HTTP 服务。覆盖时钟换算与暂停、重新开始、调度余量、时值与 BPM、首尾休止符、空练习、显示边界、命中窗口边界、延迟后补判、结束边界、重叠窗口最近匹配、等距优先较早目标、跳过目标不重复结算，以及窗口前误敲不消耗目标、目标耗尽后的连续误敲。整轮序列还验证逐帧与延迟过期检查的结果一致。

结果统计测试覆盖所有命中等级、漏敲、误敲及其组合、零目标、计数准确性、输入记录不被修改，以及结束前补齐漏拍后再汇总。

输入回归覆盖 0／80／200ms 分发延迟、epoch 时间戳、暂停恢复与时钟不连续、新轮拒收旧事件、RAF 先补漏后收到输入、自然结束后修正、乱序和无效输入，以及不同 BPM 下密集三连音／十六分序列的唯一结算。

`tests/tapping-precision.test.mjs` 覆盖三档窗口的完美／命中边界、结束等待、密集最近匹配、独立快照、本地保存和失败回退。浏览器还应验证设置刷新恢复、当前轮不变而下一轮生效，以及试听和听写不受偏好变化影响。

多小节测试覆盖连续时间、全局事件编号、整小节休止、跨界提前命中、最终结算，以及误敲位置的插值和边界限制。

这些是时间模型和纯判定/统计/位置映射函数的测试：音频暂停通过固定模拟时钟读数验证，不代表真实浏览器暂停测试；声音是否可听、键盘监听、结果展示、React/RAF 生命周期和设备延迟仍需浏览器验证。

浏览器回归重点：

- BPM 调速：拖动过程中播放不停止，移出轨道松手后只应用一次；斜向触摸拖动不被滚动中断，真正取消才恢复原速度。数字输入失焦／回车生效，相同值、空值、越界和小数不打断当前轮；方向键与 Home／End 可用。改速前后击拍 SVG／音符节点保持同一实例，旧高亮、标记和结果清空；异步准备期间调速不能让旧请求重新启动。改速后听写／自定义编辑草稿保留。
- 控制时钟与事件时间，让 RAF 先显示漏拍，再分发发生在目标起点的旧按键：应改成命中，仅为本次按键安排一次短音。
- 自然结束后送达终点前的输入：允许修正“未通过／通过”，不补响；终点后实际输入无效。
- 手动停止、重新开始或换题后分发旧时间戳：不产生判定或声音。
- 挂起 AudioContext 后恢复：暂停期间的事件无效，恢复后的新输入可以正常判定。
- 不替换浏览器时钟，用真实键盘事件路径敲击：每次有效输入只发声一次，重算不重播历史声音。

整轮重算的耗时应单独检查，不能将其与 VexFlow 重绘或设备音频延迟混为一谈。本机 Node 抽测 512 条敲击、1,000 次重算，P95 约 0.02ms；这不是手机性能保证，也不作为自动测试的固定时间阈值。

密集小节按 VexFlow 最小排版测量、行首符号余量及每事件阅读间距确定最小宽度，优先减少每行小节数，极窄屏仍整体缩放；谱面和反馈共用缩放坐标。320px 屏幕上的密集谱面仍然较小，尚未增加放大阅读功能。

十六分音符在 BPM 120 下间隔 125ms，相邻命中窗口会重叠，按窗口内最近待判定目标匹配。漏掉第一音后准时敲第二音，第一音记漏拍、第二音完美，后续可正常继续。选择精度档位不改变这条匹配规则；测试覆盖 60、120、240 BPM 的三连音与十六分序列、完整命中和漏拍恢复。


## 小三连与整数音乐时值

小节使用 `elements`，元素可以是普通 `RhythmEvent` 或 `{ kind: "triplet", notes: [...] }`。三连音组恰好包含三个无附点八分音符，共占一拍；允许从非拍头位置开始并跨越拍界，但整组不能超出小节。不支持组内休止符、其他时值或嵌套。三连音始终独立连梁，不与前后普通音符相连。预设题目仍可采用拍头开始的简单节奏，不限制模型和编辑器的输入位置。

`expandRhythmElements()` 统一输出独立事件、小节内起点 tick、时长 tick 和三连音组下标。每四分拍 24 ticks，八分 12、十六分 6、附点十六分 9、三连音每音 8；每小节校验总和为 96。小节和事件音乐位置使用整数累计，再按 `绝对 tick / 24 * (60000 / BPM)` 独立换算起点和终点，不累计近似的三分之一拍毫秒数。

`eventIndex` 仍是展开后包含休止符的全局事件编号。三连音的三个音符分别发声、高亮和判定；判定窗口及统计不变。VexFlow Tuplet 在排版前关联三个八分音符，按 3:2 改变内部时值并显示“3”，每组独立连梁。内部 24 ticks 不是 VexFlow 的时间单位。
