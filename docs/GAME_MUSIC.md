# 游戏音乐制作约定

关卡按实际乐谱声明声部，并为每个声部选择 GeneralUser GS 音色。声部数量、名称、乐器及击拍职责都由曲目决定；同一乐器可以对应多个声部。需敲击的音符应清晰，自动声部提供音乐支撑。

这是跨关卡的制作依据，不要求每首曲子的编配相同。实际听感仍需游玩确认。音乐机制见 [架构说明](ARCHITECTURE.md#声音与试听)。

## 音源与发声

所有游戏曲目共用完整 GeneralUser GS 音色库，通过 SpessaSynth AudioWorklet 实时发声，使用音色原生采样、循环和释放包络。无需逐种乐器添加音频文件；声部指定零起算的 `program`、可选 `bank` 及旋律／鼓组类型，鼓组以 MIDI 键位选择鼓件。当前关闭合成器混响和合唱。

音源来源、许可和校验清单见[游戏音源](../frontend/src/game-content/shared/audio/README.md)。命中与自动示范共用音符数据及发声路径；改变速度只调整起止时间，不改变音高。局部练习对跨界延音重新起音并保留剩余时值，不新增击拍目标，不模拟采样中途精确续接。

## 编配

曲目按实际乐谱声明独立声部，每个声部自行选择音色、音量与音符；无需遵循下表的固定组合。同一乐器可有多个声部，鼓组也可用一个声部包含不同鼓键。多声部结构、击拍映射见[架构说明](ARCHITECTURE.md#声音与试听)。常用 GS 音色名称在 `frontend/src/game-content/shared/audio/generalUser.ts`，也允许直接指定 bank/program。

下表是原有自动伴奏模板的行为，作为制作工具保留，不是播放器的声部限制。

| 声部 | 疏朗 | 律动 |
| --- | --- | --- |
| 和声 | 每小节一次长和弦 | 每小节四次短和弦，含反拍 |
| 贝斯 | 每小节一次长根音 | 每小节四次短根音 |
| 底鼓 | 首拍 | 首拍、反拍及第三拍 |
| 边击 | 第三拍 | 第二、第四拍 |
| 踩镲 | 每两拍 | 每半拍 |

键盘谱或多声部谱可提供显式伴奏事件，替代自动和弦模板，不叠加额外鼓或贝斯。具体声部分工、谱面来源和简化取舍记录在所属关卡 README。

自动编配关卡拥有旋律、和弦和段落风格选择；共用伴奏事件与增益由 `game-content/shared/harmony.ts` 维护。N.C. 所有伴奏声部静默；变拍号小节只在实际拍数内排程；小节内换和弦时更新和声与低音，旧和声在边界释放。

## 音量平衡

主旋律增益不随编配改变；不对不同曲目独立做整体响度归一化，不自动抬高总音量，不用压缩器掩盖配器失衡。每个声部用 `gain` 调整输出平衡，用音符 `velocity` 与可选 `velocityScale` 控制演奏力度；两者不可混为一谈。和弦展开辅助按音数平方根分配单音力度。可选伴奏模板的初始值集中在 `game-content/shared/harmony.ts`，不是所有曲目必须照搬的标准。

修改音源或编配后同时检查完整混音和主旋律贡献，保留削波余量。整体更安静可以接受；不可为了追求响度重新盖住旋律。

## 验收

- 自动试听：主旋律在长音、密集短音及不同音区均清楚，伴奏仍有支撑。
- 实际敲击：命中稍早、稍晚仍能听清自己弹奏的音；误敲不额外触发旋律。
- 调整 BPM、局部范围、停止、重试和离页：无旧声音复活；末音自然释放，局部伴奏按范围收音。
- 用至少两首不同旋律验证共用方案，不以单首精修替代风格验证。

浏览器自动回归能验证排程、音高、峰值与清理，不能替代用户对声部平衡和音乐风格的实际试听。
