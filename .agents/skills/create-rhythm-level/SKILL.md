# 制作节奏游戏关卡

交付能在项目中打开、示范和实际击拍的关卡，包含与曲目相配的背景、路线视觉和素材配置，并说明谱面来源及改编取舍。声部结构由乐谱决定，击拍来源与音色分别选择。用户已有的配器、范围、难度和美术要求优先；修改已有曲目时只处理本次要求。

本技能位于仓库 `.agents/skills/create-rhythm-level/`，下文命令和代码路径以仓库根为基准。先读仓库 [AGENTS.md](../../../AGENTS.md)。

## 先确定输入和落点

- 查看提供的全部谱页或数据，确认页序、曲名、编曲版本与制作范围。需要读取图片或 PDF 时实际查看谱面；OCR 和文件名只能辅助定位。
- 先从材料及上下文推导拍号、速度、声部和击拍来源；只有缺页、关键符号模糊或要求相互冲突时才询问，其他明确段落可以继续处理。仅有曲名不足以宣称完成逐音转录。
- 读取[内容归属与注册规则](../../../frontend/src/game-content/README.md#内置内容与本地曲目包)，确定本地或内置内容。额外曲目默认放 `frontend/level-packs/levels/<id>/`；已有曲目在原目录修改。先搜索 ID，保持目录名、ID 和默认导出一致。本地内容自动发现，无需修改核心 catalog，也不强制加入 Git。
- 开始音乐制作前读[音乐制作约定](../../../docs/GAME_MUSIC.md)及[声音与试听架构](../../../docs/ARCHITECTURE.md#声音与试听)。字段和校验以当前 [MultipartScore.ts](../../../frontend/src/game/core/MultipartScore.ts) 和 [GameLevel.ts](../../../frontend/src/game/core/GameLevel.ts) 为准，不复制整套类型到关卡。

## 读谱并建立演奏顺序

输入包含 `.mid`／`.midi` 时，先读 [MIDI 制作流程](references/midi-workflow.md)，解析演奏事件、核对声部与完整时间轴，再进入音乐与击拍编写。MIDI 已记录实际演奏顺序；以下展开反复等步骤针对纸面谱，不对 MIDI 重复展开。

先在制作笔记或代码附近建立“谱页／书面小节 → 实际演奏小节”的对应，展开反复、跳房与返回段落，保持各声部使用同一条时间轴。小节总数和段落应能回查原谱，而不是靠不断复制音符凑到预计时长。

逐声部核对谱号、调号、临时升降号的有效范围、移调乐器的实际音高、休止、弱起、连音及延音。延音线合并同音持续时间；连奏弧保留各次起音；同拍和弦中不同释放时间分别保存。休止和纯延音小节仍占演奏时间。

现有模型用四分音符拍位，支持 2/4、3/4、4/4 及首小节弱起，BPM 恒定。遇到其他拍号或自由速度，先说明限制和可选改编；不能悄悄改拍号或扩展引擎。装饰音、踏板、滑奏等取舍记入关卡 README，明确哪些来自谱面、哪些是新增编配、哪些尚未核实。可读材料不足的部分不要编造为原谱。

完成这一阶段时，应能说明演奏顺序、声部分工、时长依据及未解决的谱面问题。

## 编写音乐与击拍

按实际声部建立稳定的 `parts`，同一乐器允许多个声部，数量不固定。没有击拍职责的声部也正常保留；不要为了接力把不同声部合并成一个“主旋律”槽。

- 用 `beat`、`duration` 保存真实起止，用声部内唯一音符 ID 建立引用。常用音色从 [generalUser.ts](../../../frontend/src/game-content/shared/audio/generalUser.ts) 选择，其他音色按模型指定 bank/program；无需复制 SF2 或为每个乐器新增音频文件。
- 单独编写 `hits`：每组引用同拍音符，可包含和弦或多个声部；曲中可以切换击拍来源。未被引用的音符自动演奏。适合选择整个声部时使用 `hitsFromParts`，选择部分音符时显式编写引用，不把音符复制到另一声部来触发。
- 首次编写跨声部映射时，读[短例子](references/part-hits-example.md)。例子只演示引用关系，不作为所有曲目的声部或路线模板。
- 规则的等长小节可复用 [KeyboardScore.ts](../../../frontend/src/game/audio/KeyboardScore.ts)。`performKeyboardPart` 默认带 swing；直拍曲明确传 `.5`。弱起、变拍号和独立复调用明确拍位或适合的制作函数表达；不要把不适用的谱面塞入等长小节辅助函数。
- 可选伴奏使用 [harmony.ts](../../../frontend/src/game-content/shared/harmony.ts) 或曲目自己的制作函数，结果仍是普通声部。已有完整配器时按谱保留；只有单旋律时先保留独奏，用户要求编配或任务已明确授权时再添加伴奏，并记录新增内容。

先运行 `compileMultipartScore` 检查音符、引用和小节边界，再检查击拍分布。音量按音乐制作约定调节，不把“没有削波”当作混音已合格。

## 路线与入口

用 `GameLevel` 组织入口；本地关卡默认导出，内置关卡按内容文档注册。新增关卡使用清楚的正式名称，不附带无意义的试验后缀。

路线从真实击拍时间生成。读 [OrbitTrack.ts](../../../frontend/src/game/core/OrbitTrack.ts)，用 `twirlTilesAtBeats` 按拍位描述转向，通过 `speedChanges` 调整旋转速度。长休止导致间隔不合法时，先检查转速事件和已有建轨能力；不要加假击拍或缩短音符来绕过路线校验。能力不足时明确提出实现缺口及取舍。

连接完整路线检查重叠、交叉、转向及段落衔接，再在实际跟随中检查可读性；通过数据校验不等于路线可玩。旋转速度独立于音乐 BPM。

## 背景与游戏视觉

“制作一个关卡”默认包含该曲目的视觉制作；用户明确只改音乐或指定沿用主题时，保留已有美术。共享主题可用于调试音乐，但不能把临时背景当作完整视觉交付。

1. **形成视觉方案**：读 [DESIGN 的游戏像素主题约定](../../../frontend/DESIGN.md#游戏像素主题)和[内容素材规则](../../../frontend/src/game-content/README.md#公共素材)。根据曲目情绪、节奏与用户提供的视觉参考，明确场景主题、主体、色调、中央读路留白和取景范围。按仓库 AGENTS 的 Claude Code 约定取得设计方案，Codex 实现；不要仅凭曲名默认使用夜景或霓虹。所需设计工具不可用时明确列为未完成项，继续音乐工作。
2. **制作背景资产**：像素场景读取 [pxl-pixel-art skill](../pxl-pixel-art/SKILL.md)，保存可编辑源并导出图片。本地关卡的源与图片分别放在所属目录的 `art/`、`assets/`，通过 `?url` 导入；图片尺寸、源文件及导出参数按内容文档声明，避免复制其他曲目的专属背景。
3. **接入关卡视觉**：在入口配置 `visualTheme`、背景取景和压暗、场景底色及道路材质／色阶，检查双球、路径和转向标记与背景的区分。沿用共享双球、按钮、判定和结束反馈规则，不为单曲覆盖公共 UI。列表封面复用关卡的场景资源，核对实际裁切。只有音乐段落确实需要换景时才配置 `visualTimeline`，不为凑变化强制制作多个背景。
4. **在游戏中验收**：把背景与完整路线放在一起看，检查开头、密集路段、转向、选段进入及结束状态；静态原图好看不等于游玩时可读。按 DESIGN 检查桌面与宽屏实际舞台的主体裁切、道路对比及控件遮挡；手机检查按任务需要进行，不作为默认必检项。范围限定为本次新增场景和受影响状态，不顺带全面检查与任务无关的应用页面。实现后对照设计方案，必要时请同一 Claude Code 会话复核具体偏差。

这一阶段完成时，应有正式背景、可编辑源、有效的视觉与资源声明，以及实际游戏画面的检查结果。关卡 README 记录场景表达和取景取舍；仍使用临时主题时明确标注视觉尚未完成。

## 验证与交付

按[前端验证与隔离浏览器流程](../../../frontend/README.md#浏览器回归)运行对应检查；命令以 `frontend/package.json` 为准。在 `frontend/` 执行前端要求的测试、lint、构建和架构校验，本地曲目另运行 `npm run validate:game:local`，内置内容运行 `npm run validate:game`。改了预设题库时再做该题库的校验。

浏览器验收针对本次曲目，确认列表唯一入口、直接路由、显示名称和素材加载。选开头、密集段、跨小节延音、声部接力和结尾中与本曲有关的片段，检查示范、实际命中和局部练习。全曲音乐数据核对完整时间轴，音频检查优先短片段；需要整曲审听时再完整播放。现有浏览器脚本若写死《微光》，其通过不能替代新曲目的验证。

实际播放需核对可击拍音符清晰度、伴奏平衡、音符收尾和停止后的静音。峰值测量只能作为辅助；无法实际试听或有页面缺失时，明确标注尚未验收的范围，不宣称已完整还原或听感合格。

交付时给出关卡 ID、目录和访问路径，概述声部及击拍选择、原谱改编取舍、背景与视觉方案、通过的检查与待确认项。本地曲目说明仍被 Git 忽略；技能调用本身不代表授权提交、推送或发布。
